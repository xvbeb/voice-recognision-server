# q Admin v1 — один владелец

## Что реализовано

`/admin` требует серверную сессию и перенаправляет на `/admin/login`, если её нет.
Страница входа публична, данных на ней нет. `/api/admin/stats`,
`/api/admin/logout` и JS панели требуют авторизацию на сервере. CSS входа
публичен и не содержит настроек или статистики. При некорректных/отсутствующих
секретах все эти маршруты возвращают 404. Публичные API не содержат статистики.

Пароль передаётся обычной HTML-формой POST по HTTPS, не через URL или JavaScript.
Используется Argon2id-хеш из Variables. Нет регистрации, приглашений, ролей или
второго администратора. Возможны несколько сессий одного владельца.

Сессия: случайные 256 бит, в PostgreSQL только SHA-256 токена, версия авторизации
и срок. Cookie `__Host-q_session`: HttpOnly, Secure, SameSite=Strict, Path=/,
без Domain; абсолютный TTL 1 час, без бесконечного продления. Выход удаляет
серверную сессию. Смена хеша пароля или session secret инвалидирует старые сессии.
POST входа защищён подписанным CSRF-токеном на 10 минут и проверкой Origin.
POST выхода требует CSRF-токен сессии и Origin. Панель и API имеют no-store,
CSP без CDN/unsafe-eval и запрет встраивания во фреймы.

Лимит: всего 5 попыток входа (включая успешные) за фиксированное окно 15 минут
на единственного владельца. PostgreSQL делает проверку общей и атомарной между
процессами/репликами. IP, User-Agent и Telegram ID не используются и не хранятся.
При атаке лимит может временно заблокировать вход самому владельцу; существующие
сессии продолжают работать. Это осознанное ограничение v1. Отказ БД закрывает
вход и чтение статистики, а не отключает защиту.

## Учёт событий

Один middleware создаёт один UUID на каждый POST `/transcribe`: успех, ошибка,
422 валидации и ответ из кэша. Повторный HTTP-запрос — отдельная попытка, даже
если файл тот же. Запись с тем же UUID защищена primary key + ON CONFLICT.
Время обработки измеряется до завершения ответа, без времени записи статистики.
Запись выполняется после отправки ответа с общим бюджетом 750 мс.

Никакие тела запросов/ответов, аудио, тексты, имена файлов, IP, ключи или заголовки
не попадают в события. Ошибки имеют безопасный код `http_429`, `http_504` и т.п.;
необработанный сбой — `request_failed`. Источник всегда `unknown`: существующие
клиенты не присылают достоверного признака. Длительность — NULL: сервер её не
вычислял, и метаданным клиента не доверяем. voice/circle определяется по уже
нормализованному MIME, unknown — если этот этап не достигнут/тип неподдерживаемый.

Сбой записи не влияет на транскрибацию, логируется только
`transcription_event_write_failed`. Запись best-effort: при отказе БД, остановке
процесса или отмене запроса событие может быть потеряно. Очереди восстановления
нет; dashboard показывает сохранённые события, не полную историю во время отказа.
Старые запросы до подключения статистики не восстанавливаются.

UTC: timestamptz и timezone-aware datetime. По умолчанию Europe/Kyiv, есть UTC.
Сегодня/7/30 дней — календарные дни выбранного часового пояса, включая текущий,
с учётом DST. Основные карточки, график и 50 последних событий фильтруются по
выбранному периоду; три карточки успешных today/7/30 независимы от этого фильтра.
Среднее время — по всем попыткам, success rate — success / total, включая кэш.
Известная длительность суммируется только для success; при отсутствии данных
показывается «—», не выдуманный ноль. Дни без запросов не показаны на графике.
Пустая доступная база показывает 0 событий; недоступная база — 503 и явную ошибку.
Все выборки одного ответа выполняются в согласованном repeatable-read snapshot.

## Railway Variables

Существующие Gemini Variables не менять.

- `DATABASE_URL`: ссылка на PostgreSQL в том же Railway environment,
  например `${{Postgres.DATABASE_URL}}` (имя сервиса может отличаться).
- `ADMIN_PASSWORD_HASH`: Argon2id-хеш. Создать локально в backend:
  `python tools/admin_password.py`. Пароль вводится скрыто, хеш выводится для
  вставки в Variables. Не сохранять пароль/хеш в Git, скриншоты или логи.
- `ADMIN_SESSION_SECRET`: независимые 32+ случайных символа. Локально:
  `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
- `ADMIN_ORIGIN`: `https://voice-recognision-server-production.up.railway.app`
  без завершающего слеша. Приложение требует HTTPS; не ослаблять Secure cookie
  для локальной HTTP-проверки.

`ADMIN_PASSWORD` не используется. Доступ по умолчанию отключён.
Session secret хранится только в Variables; все реплики используют один секрет.
На Windows для ZoneInfo установлена зависимость tzdata; Railway использует ту же
IANA-зону Europe/Kyiv.

## Подключение PostgreSQL и порядок публикации

Ничего из этого не выполнялось в production. Нужны подтверждение владельца и
проверка целевого Railway project/environment/service.

1. Создать PostgreSQL-сервис в существующем Railway-проекте/environment.
   Настроить резервные копии по требованиям владельца. Не открывать БД публично
   для работы API: использовать private networking и reference DATABASE_URL.
2. Подготовить Variables backend. Для безопасного поэтапного запуска можно пока
   оставить `ADMIN_PASSWORD_HASH` пустым — панель останется закрыта.
3. Установить зависимости из requirements.txt. Удобный вариант Railway: после
   подтверждения задать Pre-deploy Command `python tools/migrate.py --apply`;
   она выполняется перед запуском новой версии с Variables и доступом к private
   network, а ошибка останавливает деплой. Либо применить миграцию **один раз**
   к выбранной БД из среды, имеющей к ней доступ:
   `python tools/migrate.py --apply`.
   Команда читает DATABASE_URL из окружения, не из аргументов. Создаёт только
   transcription_events, admin_sessions, admin_login_limit и индексы, в транзакции.
   Миграция идемпотентна; автоматической миграции при старте FastAPI нет.
   Private Railway URL обычно недоступен с ноутбука: выполнить SQL через
   согласованный доступ к БД или миграционную команду в Railway, не подменять
   production URL локальным тестовым.
4. После миграции развернуть проверенный backend; включить секреты админки.
   Стартовая команда FastAPI остаётся прежней. Backend public/ включить как раньше.
5. Проверить /health, /install, /q-runtime.js; без cookie /api/admin/stats должен
   вернуть 401, /admin — перенаправить на вход. Войти, проверить пустую/непустую
   базу и выход. Выполнить только разрешённую тестовую транскрибацию.
6. Откат: развернуть предыдущую версию приложения; таблицы можно оставить.
   Быстро отключить админку — очистить ADMIN_PASSWORD_HASH. Статистика продолжит
   записываться, если DATABASE_URL задан. Для отключения статистики убрать
   DATABASE_URL (будут безопасные предупреждения о пропущенных записях).

Не выполнять push, миграцию production или railway up без подтверждения.

## Локальные проверки

```sh
python -m unittest discover -s tests -v
# Дополнительно: тесты на реальном PostgreSQL, ТОЛЬКО отдельная локальная БД *_test.
Q_TEST_DATABASE_URL=postgresql://127.0.0.1:55439/q_admin_test python -m unittest discover -s tests -v
```

Тесты PostgreSQL создают схему и очищают таблицы в тестовой БД. Они отказываются
работать с нелокальным хостом или именем БД без суффикса _test.
Без Q_TEST_DATABASE_URL интеграционные DB-тесты явно skipped.

Browser-тест использует Chrome и Playwright из bookmarklet/node_modules:
`Q_ADMIN_TEST_URL=https://127.0.0.1:8767 Q_ADMIN_TEST_PASSWORD='<synthetic-password>' node tests/admin_browser.cjs`.
Нужен локальный HTTPS backend с тестовыми секретами и заполненной тестовой БД;
тест проверяет вход, карточки, график, период, mobile, ошибку загрузки и выход.
Он не выполняет реальные вызовы Gemini. Для тестирования сертификата используется
ignoreHTTPSErrors только в тестовом браузере, не в production.

## Расширение позднее

stats_store — репозиторий данных; stats_middleware — измерение попыток;
admin_auth — только владелец; admin_routes/static — представление. Будущие
активации, пользователи и ограничения должны иметь собственные миграции и
сервисы, без изменения логики статистики/авторизации GameSpace. Таблиц промокодов,
пользователей, подписок и биллинга в v1 нет.

Официальная документация: [PostgreSQL Railway](https://docs.railway.com/databases/postgresql), [Pre-deploy command](https://docs.railway.com/infrastructure-as-code/reference).
